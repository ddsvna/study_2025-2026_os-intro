# Ответы на контрольные вопросы
1. Что такое системы контроля версий (VCS) и для решения каких задач они предназначаются?
Это средства для хранения истории изменений, совместной работы, отката версий и объединения изменений.
2. Объясните следующие понятия VCS и их отношения: хранилище, commit, история, рабочая копия.
-Хранилище - место хранения всех версий проекта.
-Commit - сохранения изменений с комментарием.
-История - последовательность всех коммитов.
-Рабочая копия - локальные файлы пользователей.
3. Что представляют собой и чем отличаются централизованные и децентрализованные VCS? Приведите примеры VCS каждого вида.
-Цетрализованные: один сервер, все операции через него.
-Децентрализованные: каждый пользователь имеет полный репозиторий, сервер не обязателен.
4. Опишите действия с VCS при единоличной работе с хранилищем.
Инициализация репозитория, добавление файлов, коммитов, просмотр статуса, просмотр изменений.
5. Опишите порядок работы с общим хранилищем VCS.
Получить изменения, затем создать ветку, затем внести правки, далее добавить файлы, закоммитить, отправить на сервер.
6. Каковы основные задачи, решаемые инструментальным средством git?
Управление версиями, работа с ветками, хранение истории, слияние изменений, распределенная разработка.
7. Назовите и дайте краткую характеристику командам git.
git init, git status, git add, git commit, git diff, git pull, git push, git checkout, git merge, git branch.
8. Приведите примеры использования при работе с локальным и удалённым репозиториями.
-Локальный: git init, git add, git commit.
-Удаленный: git remote add, git push, git pull.
9. Что такое и зачем могут быть нужны ветви (branches)?
Параллельные линии разработки дял изоляции изменений и удобного слияния.
10. Как и зачем можно игнорировать некоторые файлы при commit?
Использовать .gitignore для исключения временных и ненужных файлов.
